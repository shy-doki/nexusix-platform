## 一、文档总览

### 1.1 文档分类体系

NexusIX-Platform 项目文档按功能类型划分为 5 大类，统一使用中文命名，Markdown 格式：

| 分类编号 | 分类名称 | 目录路径 | 文档数量 | 说明 |
|---------|---------|---------|---------|------|
| 01 | 业务需求文档 | `docs/01-业务需求文档/` | 8 | 各模块的 PRD 设计文档，包含业务需求、功能描述、数据库设计、接口定义、测试策略 |
| 02 | 代码实现文档 | `docs/02-代码实现文档/` | 3 | 已实现模块的实现细节文档，准确反映代码实现情况 |
| 03 | 测试用例文档 | `docs/03-测试用例文档/` | 2 | 接口测试和功能测试用例文档 |
| 04 | 开发规范文档 | `docs/04-开发规范文档/` | 1 | 代码开发规范、命名约定、架构原则等 |
| 05 | 数据库脚本 | `docs/05-数据库脚本/` | 8 | 数据库 DDL 建表语句和初始化数据脚本 |

## 三、核心概念术语表

为保证全平台文档术语统一、概念准确、无歧义，特制定以下术语表。所有文档必须严格遵循此术语表。

### 3.1 架构与分层术语

| 术语 | 英文 | 含义 | 首次出现文档 |
|------|------|------|-------------|
| 控制器 | Controller | 接收 HTTP 请求，调用 Service，返回 ApiResponse | 代码开发规范文档 |
| 服务接口 | Service Interface | 业务逻辑接口，命名 `IXxxService` | 代码开发规范文档 |
| 服务实现 | Service Implementation | 业务逻辑实现，命名 `XxxServiceImpl` | 代码开发规范文档 |
| 映射器 | Mapper | 数据库访问层，基于 MyBatis-Plus | 代码开发规范文档 |
| 实体 | Entity | 数据库表对应的 Java 对象，命名 `SysXxx`/`BizXxx` | 代码开发规范文档 |
| 请求传输对象 | RTO (Request Transfer Object) | 接口入参对象，命名 `XxxAddRTO`/`XxxUpdateRTO`/`XxxQueryRTO` | 代码开发规范文档 |
| 视图对象 | VO (View Object) | 接口出参对象，命名 `XxxCommonVO`/`XxxDetailVO`/`XxxTreeVO` | 代码开发规范文档 |
| 数据传输对象 | DTO (Data Transfer Object) | 内层数据传输对象，命名 `XxxDTO` | 代码开发规范文档 |
| 转换器 | Converter | MapStruct 实体转换器，命名 `XxxConverter` | 代码开发规范文档 |

### 3.2 权限体系术语

| 术语 | 英文 | 含义 | 首次出现文档 |
|------|------|------|-------------|
| 4级权限禁用体系 | 4-Level Disabled Permission System | SYSTEM > TENANT > DEPT > ROLE > USER 五个级别 | 权限禁用测试用例文档 |
| 系统级禁用 | System Level Disabled | 系统级禁用权限，最高优先级 | IAM身份认证模块实现文档 |

## 七、文档维护规范

### 7.1 文档更新原则

1. **代码变更同步**：当代码发生变更时，对应的实现文档必须同步更新
2. **PRD 变更流程**：业务需求变更先更新 PRD 文档，再进行代码开发
3. **数据库变更同步**：表结构变更必须同步更新数据库脚本和对应模块文档
4. **术语统一**：新增术语必须先添加到本文档术语表，再在其他文档中使用

### 7.2 文档命名规范

- 业务需求文档：`{模块中文名}模块PRD.md`
- 代码实现文档：`{模块中文名}模块实现文档.md`
- 测试用例文档：`{测试范围}测试用例文档.md` 或 `{测试范围}测试文档.md`
- 开发规范文档：`{规范类型}规范文档.md`
- 数据库脚本：`{表名}.sql`（保持英文，与数据库表名一致）

### 7.3 文档版本管理

- 所有文档头部必须包含版本信息表（版本号、日期、修订人、修订说明）
- 版本号采用 `v{主版本}.{次版本}` 格式（如 v1.0、v1.1）
- 主版本：重大重构或新增章节
- 次版本：内容修订或小幅补充
