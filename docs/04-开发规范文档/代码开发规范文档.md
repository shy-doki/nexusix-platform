## 1. 概述

### 1.1 项目背景

NexusIX-Platform 是一个基于多租户架构的企业级 SaaS 平台，支持租户隔离、权限分级、组织架构管理、计费订阅、动态表单、审计日志等能力。平台采用前后端分离架构，后端为多模块 Maven 工程，共 11 个子模块。

### 1.2 技术栈

| 类别 | 技术 | 版本 |
| --- | --- | --- |
| 基础框架 | Spring Boot | 3.3.4 |
| JDK | OpenJDK | 17 |
| ORM | MyBatis-Plus | 3.5.12 |
| 认证授权 | Sa-Token + JWT | 1.42.0 |
| 数据库 | PostgreSQL | 17.x |
| 缓存 | Redis | 3.4.0 |
| 消息队列 | RabbitMQ（spring-boot-starter-amqp） | 随 Spring Boot |
| 对象映射 | MapStruct | 1.5.2.Final |
| JSON 序列化 | Fastjson2 | 2.0.54 |
| 接口文档 | Knife4j（OpenAPI3） | 4.5.0 |
| Excel 处理 | FastExcel | 1.2.0 |
| 工具库 | Lombok | 1.18.36 |

### 1.3 模块清单

| 模块 | 包路径 | 职责 |
| --- | --- | --- |
| nexusix-common | com.shy.nexusix.common | 公共工具、常量、枚举、异常、注解、切面、配置 |
| nexusix-core | com.shy.nexusix.core | 核心上下文（用户上下文、租户上下文等） |

本规范适用于 NexusIX-Platform 项目全部 11 个子模块的 Java 源码、SQL 脚本、Maven 配置及 Git 提交记录。所有新建代码必须遵循本规范，存量代码在重构时需逐步对齐。

## 2. 命名规范

### 2.1 包命名

包路径统一采用 `com.shy.nexusix.{module}.{layer}` 格式，`{module}` 为模块名（如 iam、tenant、common），`{layer}` 为分层名（controller / service / impl / mapper / entity / rto / vo / dto / converter / config / aspect / annotation / constant / enums / exception / result / utils）。

- ✓ 正例
  ```java
  package com.shy.nexusix.iam.controller;
  package com.shy.nexusix.iam.service.impl;
  package com.shy.nexusix.common.exception;
  package com.shy.nexusix.iam.rto;
  ```
- ✗ 反例
  ```java
  package com.shy.nexusix.iam.Controller;       // 层名不应大写
  package com.shy.nexusix.iam.user;             // 缺少分层
  package com.shy.nexusix.iam.controller.user;  // 多余子包
  ```

### 2.2 类命名

| 类型 | 命名规则 | 正例 | 反例 |
| --- | --- | --- | --- |
| Controller | `XxxController` | `SysUserController` | `SysUserApi` / `UserControllerApi` |
| Service 接口 | `IXxxService` | `ISysUserService` | `SysUserService` / `ISysUserServiceImpl` |
| Service 实现 | `XxxServiceImpl` | `AuthServiceImpl` | `AuthImpl` / `AuthService` |
| Mapper | `XxxMapper` | `SysUserMapper` | `SysUserDao` / `UserMapperImpl` |
| Entity（系统级） | `SysXxx` | `SysUser`、`SysTenant` | `User` / `SysUserEntity` |
| Entity（业务级） | `BizXxx` | `BizOrder`、`BizContract` | `Order` / `BizOrderEntity` |
| RTO（新增） | `XxxAddRTO` | `SysUserAddRTO` | `SysUserAddDTO` / `UserAddReq` |
| RTO（修改） | `XxxUpdateRTO` | `SysUserUpdateRTO` | `SysUserUpdateVO` |
| RTO（查询） | `XxxQueryRTO` | `SysUserQueryRTO` | `SysUserSearchRTO` |
| RTO（批量绑定） | `XxxBatchBindRTO` | `SysUserBatchBindRTO` | `SysUserBindRTO` |
| VO（通用） | `XxxCommonVO` | `SysUserCommonVO` | `SysUserVO` / `UserCommonVo` |
| VO（详情） | `XxxDetailVO` | `SysUserDetailVO` | `SysUserInfoVO` |
| VO（树形） | `XxxTreeVO` | `SysTenantTreeVO` | `TenantTree` / `SysTenantTree` |
| DTO（内部传输） | `XxxDTO` | `UserContextDTO`、`UserRoleDTO` | `UserRoleVO` / `UserRole` |
| Converter | `XxxConverter` | `SysUserConverter` | `SysUserMapper` / `UserMapStruct` |

- ✓ 正例
  ```java
  public class SysUserController { }
  public interface ISysUserService { }
  public class SysUserAddRTO { }
  public class SysUserCommonVO { }
  ```
- ✗ 反例
  ```java
  public class UserController { }      // 缺少 Sys 前缀
  public interface SysUserService { }  // Service 接口缺少 I 前缀
  public class SysUserReq { }          // 未使用 RTO 后缀
  public class SysUserVo { }           // 未使用 VO 大写后缀
  ```

### 2.3 方法命名

| 业务场景 | 命名规则 | 正例 |
| --- | --- | --- |
| 查询列表（不分页） | `queryXxxList` | `queryUserList()` |
| 分页查询 | `queryXxxPage` | `queryUserPage(page)` |
| 条件查询 | `queryXxx` | `queryUser(queryParam)` |
| 查询详情 | `queryXxxDetail` | `queryUserDetail(userCode)` |
| 查询树形结构 | `queryXxxTreeList` / `queryXxxTreePage` | `queryTenantTreeList()` |
| 新增 | `addXxx` | `addUser(addParam)` |
| 修改 | `updateXxx` | `updateUser(updateParam)` |
| 更新状态 | `updateXxxStatus` | `updateUserStatus(id, status)` |
| 删除 | `deleteXxx` | `deleteUser(id)` |
| 批量新增 | `batchAddXxx` | `batchAddUser(addParamList)` |
| 批量修改 | `batchUpdateXxx` | `batchUpdateUser(updateParamList)` |
| 批量删除 | `batchDeleteXxx` | `batchDeleteUser(ids)` |
| 批量更新状态 | `batchUpdateXxxStatus` | `batchUpdateUserStatus(ids, status)` |
| 业务动作 | 语义化动词 | `assignSubTenant`、`switchTenant`、`reviewTenant` |

- ✓ 正例
  ```java
  public ApiResponse queryUserPage(@Valid PageCommonRTO page) { }
  public Integer batchDeleteUser(List<String> ids) { }
  public ApiResponse reviewTenant(@Valid @RequestBody SysTenantReviewRTO reviewParam) { }
  ```
- ✗ 反例
  ```java
  public ApiResponse getUserList() { }            // 查询类方法应使用 query 前缀
  public ApiResponse selectUser() { }             // Service/Controller 不使用 select
  public Integer delete(List<String> ids) { }     // 缺少业务主体
  public ApiResponse doReview() { }               // 使用 do 前缀
  public ApiResponse findUserPage() { }           // 统一用 query，不混用 find
  ```

### 2.4 变量命名

- 成员变量（Service/Mapper 注入）：统一加 `i` 前缀，如 `iSysUserService`、`iAuthService`、`iSysTenantService`。
- 普通局部变量：使用 lowerCamelCase，含义清晰，禁止使用 `a`、`b`、`tmp1` 等无意义命名。

- ✓ 正例
  ```java
  @Autowired
  private ISysUserService iSysUserService;

  List<SysUserCommonVO> userList = iSysUserService.queryUserList();
  ```
- ✗ 反例
  ```java
  @Autowired
  private ISysUserService sysUserService;   // 缺少 i 前缀
  @Autowired
  private ISysUserService service;          // 缺少业务主体

  List<SysUserCommonVO> list = iSysUserService.queryUserList(); // 局部变量过于宽泛
  ```

### 2.5 常量命名

常量统一使用 `UPPER_SNAKE_CASE`（全大写下划线），语义完整，禁止缩写造成歧义。

- ✓ 正例
  ```java
  private static final long serialVersionUID = 1L;
  private static final String POINTCUT_OPERATION_LOG = "@annotation(com.shy.nexusix.common.annotation.OperationLog)";
  private static final DateTimeFormatter DATETIME_FORMATTER = DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss.SSS");
  ```
- ✗ 反例
  ```java
  private static final String pointcut = "...";   // 未全大写
  private static final String PCL = "...";        // 缩写无法理解
  public static final int Max = 100;              // 仅首字母大写
  ```

### 2.6 数据库命名

- 表名：`sys_xxx`（系统表）或 `biz_xxx`（业务表），全小写 snake_case。
- 字段名：全小写 snake_case，如 `user_code`、`create_at`、`is_deleted`。
- 索引名：普通索引 `idx_表名_字段名`，唯一索引 `uk_表名_字段名`。

- ✓ 正例
  ```sql
  create table sys_user ( id bigint not null primary key, user_code varchar(50) not null );
  comment on column sys_user.user_code is '用户编码';
  create index idx_sys_user_user_code on sys_user(user_code);
  create unique index uk_sys_user_email on sys_user(email);
  ```
- ✗ 反例
  ```sql
  create table SysUser ( id bigint, UserCode varchar(50) );  -- 含大写
  create table users ( id bigint );                          -- 缺少 sys_ / biz_ 前缀
  create index idx1 on sys_user(user_code);                  -- 索引名未包含表名字段名
  ```

### 2.7 枚举命名

所有业务枚举作为 `GlobalEnum` 的内部枚举实现 `BaseEnum` 接口，使用 `@EnumValue` 标记数据库存储字段，使用 `@JSONField(value = true)` 支持 JSON 序列化按 code 输出。枚举值采用 `UPPER_SNAKE_CASE`。

- ✓ 正例
  ```java
  public enum UserStatus implements BaseEnum {
      ENABLED("ENABLED", "启用"),
      DISABLED("DISABLED", "禁用"),
      LOCKED("LOCKED", "锁定");

      @EnumValue
      @JSONField(value = true)
      private final String code;
      private final String desc;

      UserStatus(String code, String desc) { this.code = code; this.desc = desc; }

      @Override public String getCode() { return code; }
      @Override public String getDesc() { return desc; }
  }
  ```
- ✗ 反例
  ```java
  public enum UserStatus {           // 未实现 BaseEnum
      Enabled("1", "启用"),          // 枚举值未使用 UPPER_SNAKE_CASE
      Disabled("0", "禁用");
      private String code;           // 未使用 @EnumValue 标记
  }
  ```

## 3. 代码格式规范

### 3.1 基础格式

| 项目 | 规范 |
| --- | --- |
| 缩进 | 4 个空格，禁止使用 Tab |
| 字符编码 | UTF-8（`<project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>`） |
| 行宽 | 建议不超过 120 字符 |
| 换行 | 每行只写一条语句 |
| 大括号 | K&R 风格，左括号不换行，右括号独占一行 |
| 文件末尾 | 保留一个空行 |

- ✓ 正例
  ```java
  if (user == null) {
      throw new BusinessException("用户不存在");
  }
  ```
- ✗ 反例
  ```java
  if (user == null)
      throw new BusinessException("用户不存在");  // 缺少大括号
  ```

### 3.2 import 顺序

import 按以下顺序分组，组间空行分隔，组内按字母序排列：

1. `java.*` / `javax.*`
2. `jakarta.*`
3. 第三方依赖（`com.baomidou`、`com.alibaba`、`cn.dev33`、`io.swagger`、`lombok`、`org.springframework`）
4. 项目内部（`com.shy.nexusix.*`）

- ✓ 正例
  ```java
  import java.time.LocalDateTime;
  import java.util.List;

  import jakarta.validation.Valid;
  import jakarta.validation.constraints.NotBlank;

  import com.baomidou.mybatisplus.core.metadata.IPage;
  import io.swagger.v3.oas.annotations.Operation;
  import lombok.Data;
  import org.springframework.web.bind.annotation.*;

  import com.shy.nexusix.common.result.ApiResponse;
  import com.shy.nexusix.iam.rto.SysUserAddRTO;
  ```
- ✗ 反例
  ```java
  import com.shy.nexusix.iam.rto.SysUserAddRTO;   // 项目内部混在第三方之前
  import lombok.Data;
  import java.util.List;                           // java 包混在第三方之后
  import jakarta.validation.Valid;
  ```
- ✗ 反例（使用通配符 import）
  ```java
  import java.util.*;                  // 禁止通配符 import
  import com.shy.nexusix.common.*;     // 禁止通配符 import
  ```

### 3.3 类成员顺序

类成员按以下顺序声明：

1. 静态常量（`static final`）
2. 静态变量（`static`）
3. 实例变量（字段）
4. 构造方法
5. 普通方法（public → protected → private）

- ✓ 正例
  ```java
  public class OperationLogAspect {

      private static final Logger log = LoggerFactory.getLogger(OperationLogAspect.class);
      private static final DateTimeFormatter DATETIME_FORMATTER = DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss.SSS");

      private ThreadLocal<Long> startTime = new ThreadLocal<>();

      @Pointcut(POINTCUT_OPERATION_LOG)
      public void operationLogPointcut() { }

      @Before("operationLogPointcut()")
      public void doBefore(JoinPoint joinPoint) { }
  }
  ```
- ✗ 反例
  ```java
  public class OperationLogAspect {
      @Before("operationLogPointcut()")
      public void doBefore(JoinPoint joinPoint) { }   // 方法在字段之前

      private ThreadLocal<Long> startTime = new ThreadLocal<>();

      private static final DateTimeFormatter DATETIME_FORMATTER = ...;  // 静态常量在实例变量之后
  }
  ```

### 3.4 链式调用与参数构造

实体类、RTO 统一基于 Lombok `@Data` + `@Accessors(chain = true)` 支持链式调用。构造对象时优先链式 set。

- ✓ 正例
  ```java
  SysUser user = new SysUser()
      .setUserName("admin")
      .setEmail("admin@example.com")
      .setStatus("ENABLED");
  ```
- ✗ 反例
  ```java
  SysUser user = new SysUser();
  user.setUserName("admin");
  user.setEmail("admin@example.com");
  user.setStatus("ENABLED");   // 逐行 set，未利用链式
  ```

### 3.5 类注解顺序

类注解按以下顺序声明：

1. Lombok 注解：`@Data` → `@EqualsAndHashCode` → `@Accessors`
2. 持久化注解：`@TableName`
3. 文档注解：`@Schema`
4. 框架注解：`@RestController` / `@Service` / `@Component` / `@Aspect` 等

- ✓ 正例（Entity）
  ```java
  @Data
  @EqualsAndHashCode(callSuper = false)
  @Accessors(chain = true)
  @TableName("sys_user")
  @Schema(name = "SysUser对象", description = "用户表：系统级用户实体（全局）")
  public class SysUser implements Serializable { }
  ```
- ✓ 正例（Controller）
  ```java
  @RestController
  @RequestMapping("/user")
  @Tag(name = "用户管理", description = "用户管理相关接口")
  @Validated
  public class SysUserController { }
  ```
- ✗ 反例
  ```java
  @Schema(name = "SysUser对象", description = "...")
  @TableName("sys_user")
  @Accessors(chain = true)
  @Data
  @EqualsAndHashCode(callSuper = false)
  public class SysUser implements Serializable { }  // 注解顺序混乱
  ```

## 4. 注释规范

### 4.1 类注释

类注释统一采用以下格式，必须包含 `<p>` 标签与 `@author shy`。

- ✓ 正例
  ```java
  /**
   * <p>用户管理控制器</p>
   *
   * @author shy
   */
  @RestController
  public class SysUserController { }
  ```
- ✗ 反例
  ```java
  // 用户管理控制器         // 未使用 Javadoc 格式
  @RestController
  public class SysUserController { }
  ```
- ✗ 反例
  ```java
  /**
   * 用户管理控制器          // 缺少 <p> 标签和 @author
   */
  @RestController
  public class SysUserController { }
  ```

### 4.2 方法注释

所有 public 方法必须添加 Javadoc，格式：`/** <p>方法描述</p> @param @return @throws */`。涉及业务逻辑的方法必须声明 `@throws BusinessException`。

- ✓ 正例
  ```java
  /**
   * <p>新增用户</p>
   *
   * @param addParam 新增用户信息
   * @return 新增结果行数
   * @throws BusinessException 无权限或新增失败时抛出
   */
  @PostMapping("/add")
  public ApiResponse addUser(@Valid @RequestBody SysUserAddRTO addParam) { }
  ```
- ✗ 反例
  ```java
  /**
   * 新增用户                // 缺少 <p>、@param、@return、@throws
   */
  public ApiResponse addUser(SysUserAddRTO addParam) { }

  // 新增用户               // public 方法未使用 Javadoc
  public ApiResponse addUser(SysUserAddRTO addParam) { }
  ```

### 4.3 字段注释

字段注释使用 `/** 字段描述 */` 或单行 `// 字段描述`。Entity 字段必须使用 `/** */` 并配合 `@Schema`。

- ✓ 正例
  ```java
  /** 主键ID */
  @Schema(description = "主键ID（系统用户ID）", example = "1")
  @TableId(value = "id", type = IdType.ASSIGN_ID)
  private Long id;

  /** 用户编码 */
  @Schema(description = "用户编码", example = "U001")
  @TableField(value = "user_code")
  private String userCode;
  ```
- ✗ 反例
  ```java
  private Long id;           // 无任何注释
  private String userCode;   // 无任何注释
  ```

### 4.4 行内注释

复杂逻辑必须使用 `// 注释` 说明意图，注释应解释「为什么」而非「做什么」。

- ✓ 正例
  ```java
  // 当前租户的启用/禁用分组
  if ("ACTIVE".equals(perm.getPermPolicyStatus())) {
      currentEnabledPerms.add(item);
  } else {
      currentDisabledPerms.add(item);
  }

  // 确定当前登录租户（优先主租户）
  UserTenantItemDTO currentTenant = null;
  for (UserTenantItemDTO tenant : tenantList) {
      if (Boolean.TRUE.equals(tenant.getIsPrimary())) {
          currentTenant = tenant;
          break;
      }
  }
  ```
- ✗ 反例
  ```java
  // 遍历租户              // 注释只是重复代码字面意思
  for (UserTenantItemDTO tenant : tenantList) { }

  // 如果是 ACTIVE 加入启用列表，否则加入禁用列表   // 注释重复了 if/else
  if ("ACTIVE".equals(perm.getPermPolicyStatus())) { ... }
  ```

### 4.5 TODO 标记

未完成功能使用 `// TODO: 描述` 标记，描述需明确待办内容。

- ✓ 正例
  ```java
  // TODO: 校验密码是否匹配（后续使用加密对比）
  if (!param.getPassword().equals(user.getPassword())) {
      throw new BusinessException("密码错误");
  }
  ```
- ✗ 反例
  ```java
  // TODO                    // 描述为空
  // fix later               // 描述无法理解
  ```

### 4.6 Swagger 注解

| 位置 | 注解 | 必填属性 |
| --- | --- | --- |
| Controller 类 | `@Tag` | `name`、`description` |
| 接口方法 | `@Operation` | `summary`、`description` |
| 字段（Entity/RTO/VO） | `@Schema` | `description`、`example` |

- ✓ 正例
  ```java
  @Tag(name = "用户管理", description = "用户管理相关接口")
  public class SysUserController {

      @Operation(summary = "查询用户列表", description = "返回所有用户列表")
      @GetMapping("/list")
      public ApiResponse queryUserList() { }
  }

  @Schema(description = "用户编码", example = "U001")
  private String userCode;
  ```
- ✗ 反例
  ```java
  @Tag(name = "用户")                              // 缺少 description
  public class SysUserController { }

  @Operation(summary = "列表")                     // summary 含义模糊，缺少 description
  @GetMapping("/list")
  public ApiResponse queryUserList() { }

  private String userCode;                         // 缺少 @Schema
  ```

## 5. 架构原则

### 5.1 分层架构

严格遵循 `Controller → Service → Mapper` 单向调用链，禁止跨层调用或反向依赖。

| 层 | 职责 | 禁止 |
| --- | --- | --- |
| Controller | 参数接收、参数校验、调用 Service、包装 ApiResponse | 直接操作 Mapper、写业务逻辑 |
| Service | 业务逻辑、事务控制、对象转换 | 直接返回 HTTP 相关对象 |
| Mapper | 数据库访问 | 写业务逻辑 |

- ✓ 正例
  ```java
  // Controller 只调用 Service
  @GetMapping("/list")
  public ApiResponse queryUserList() {
      List<SysUserCommonVO> userList = iSysUserService.queryUserList();
      return ApiResponse.success(userList);
  }

  // Service 实现业务，调用 Mapper
  @Service
  public class AuthServiceImpl implements IAuthService {
      @Autowired private SysUserMapper sysUserMapper;
  }
  ```
- ✗ 反例
  ```java
  // Controller 直接注入 Mapper，跨层调用
  @RestController
  public class SysUserController {
      @Autowired private SysUserMapper sysUserMapper;   // 禁止
      public ApiResponse queryUserList() {
          return ApiResponse.success(sysUserMapper.selectList(null));
      }
  }
  ```
- ✗ 反例（Service 返回 HTTP 对象）
  ```java
  public ResponseEntity queryUser() { }   // Service 不应感知 HTTP
  ```

### 5.2 模块划分

11 个模块的职责边界：

| 模块 | 职责 | 依赖方向 |
| --- | --- | --- |
| nexusix-common | 公共工具、枚举、异常、注解、切面、配置 | 被所有模块依赖 |
| nexusix-core | 用户/租户上下文 DTO | 依赖 common |
| nexusix-iam | 认证、用户、角色、权限、部门策略 | 依赖 common、core |
| nexusix-tenant | 租户管理、层级、注册审核 | 依赖 common、core、iam |
| nexusix-org | 组织架构 | 依赖 common、core |
| nexusix-system | 系统配置、字典 | 依赖 common、core |
| nexusix-audit | 审计日志落库 | 依赖 common |
| nexusix-notify | 通知服务 | 依赖 common |
| nexusix-billing | 计费订阅 | 依赖 common、tenant |
| nexusix-dynamic | 动态表单 | 依赖 common |
| nexusix-boot | 启动聚合 | 依赖全部模块 |

- ✓ 正例：`nexusix-iam` 依赖 `nexusix-common`，在 pom 中声明：
  ```xml
  <dependency>
      <groupId>com.shy.nexusix</groupId>
      <artifactId>nexusix-common</artifactId>
  </dependency>
  ```
- ✗ 反例：`nexusix-common` 反向依赖 `nexusix-iam`，导致循环依赖。

### 5.3 依赖管理

版本号统一在父 pom 的 `<properties>` 与 `<dependencyManagement>` 中声明，子模块引入依赖时**不写版本号**。

- ✓ 正例（子模块 pom）
  ```xml
  <dependency>
      <groupId>com.baomidou</groupId>
      <artifactId>mybatis-plus-spring-boot3-starter</artifactId>
      <!-- 不写 version，由父 pom 统一管理 -->
  </dependency>
  ```
- ✗ 反例（子模块 pom 自行指定版本）
  ```xml
  <dependency>
      <groupId>com.baomidou</groupId>
      <artifactId>mybatis-plus-spring-boot3-starter</artifactId>
      <version>3.5.12</version>   <!-- 子模块禁止写版本号 -->
  </dependency>
  ```

### 5.4 数据传输

数据流转严格遵循 `RTO（请求入参）→ Entity → VO（响应出参）`，对象转换使用 MapStruct（`XxxConverter`）。Controller 不直接接收/返回 Entity。

- ✓ 正例
  ```java
  // 入参 RTO
  public ApiResponse addUser(@Valid @RequestBody SysUserAddRTO addParam) {
      Integer affectedRows = iSysUserService.addUser(addParam);
      return ApiResponse.success(affectedRows);
  }

  // Service 内部使用 Converter 转换
  SysUser entity = SysUserConverter.INSTANCE.toEntity(addParam);
  sysUserMapper.insert(entity);
  ```
- ✗ 反例
  ```java
  // Controller 直接接收 Entity
  public ApiResponse addUser(@RequestBody SysUser user) { }   // 禁止
  // Service 直接返回 Entity
  public SysUser queryUserDetail(String userCode) { }         // 禁止，应返回 VO
  ```

- ✓ 正例

## 6. 实体与数据传输规范

### 6.1 Entity 规范

- 主键：`@TableId(value = "id", type = IdType.ASSIGN_ID)`，雪花算法生成 `Long`。
- 字段：每个字段必须 `@TableField(value = "snake_name")`。
- 文档：每个字段必须 `@Schema(description = "", example = "")`。
- 时间：`LocalDateTime` 字段必须 `@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss", timezone = "GMT+8")`。
- 序列化：实现 `Serializable`，声明 `serialVersionUID`。

- ✓ 正例
  ```java
  @Data
  @EqualsAndHashCode(callSuper = false)
  @Accessors(chain = true)
  @TableName("sys_user")
  @Schema(name = "SysUser对象", description = "用户表：系统级用户实体（全局）")
  public class SysUser implements Serializable {

      private static final long serialVersionUID = 1L;

      /** 主键ID */
      @Schema(description = "主键ID（系统用户ID）", example = "1")
      @TableId(value = "id", type = IdType.ASSIGN_ID)
      private Long id;

      /** 用户编码 */
      @Schema(description = "用户编码", example = "U001")
      @TableField(value = "user_code")
      private String userCode;

      /** 最后登录时间 */
      @Schema(description = "最后登录时间", format = "date-time", example = "2026-06-12 15:45:30")
      @JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss", timezone = "GMT+8")
      @TableField(value = "last_login_at")
      private LocalDateTime lastLoginAt;
  }
  ```
- ✗ 反例
  ```java
  @Data
  public class SysUser {                 // 缺少 @TableName/@EqualsAndHashCode/@Accessors

      private Long id;                   // 缺少 @TableId、@Schema、@TableField

      @TableField("last_login_at")
      private LocalDateTime lastLoginAt; // 缺少 @JsonFormat 时区
  }
  ```

### 6.2 RTO 规范

- 校验注解：必填字段使用 `@NotBlank` / `@NotNull`，长度用 `@Size`，格式用 `@Pattern`，枚举用 `@EnumField`。
- 文档：每个字段必须 `@Schema(description, example)`。
- 时间：日期使用 `@JsonFormat`，日期 `yyyy-MM-dd`，日期时间 `yyyy-MM-dd HH:mm:ss`。
- 校验消息：必须提供中文 `message`。

- ✓ 正例
  ```java
  @Data
  @Schema(description = "用户新增请求对象")
  public class SysUserAddRTO {

      /** 用户编码 */
      @NotBlank(message = "用户编码不能为空")
      @Schema(description = "用户编码", example = "U001")
      private String userCode;

      /** 用户名（登录名） */
      @NotBlank(message = "用户名不能为空")
      @Size(min = 3, max = 20, message = "用户名必须在3-20字符之间")
      @Schema(description = "用户名（登录名）", example = "admin")
      private String userName;

      /** 电子邮箱 */
      @Pattern(regexp = EMAIL, message = "电子邮箱格式不正确")
      @Schema(description = "电子邮箱", example = "admin@example.com")
      private String email;

      /** 状态 */
      @NotNull(message = "状态不能为空")
      @EnumField
      @Schema(description = "状态", example = "启用")
      private GlobalEnum.UserStatus status;
  }
  ```
- ✗ 反例
  ```java
  @Data
  public class SysUserAddRTO {

      private String userCode;            // 无校验、无 @Schema

      @NotBlank
      private String userName;            // @NotBlank 缺少 message

      @Pattern(regexp = ".*")             // @Pattern 缺少 message
      private String email;
  }
  ```

### 6.3 VO 规范

- 字段必须 `@Schema(description, example)`。
- 时间字段必须 `@JsonFormat`。
- 敏感字段（密码、token）不得出现在 VO 中。

- ✓ 正例
  ```java
  @Data
  @Schema(description = "用户公共视图对象")
  public class SysUserCommonVO {

      /** 用户编码 */
      @Schema(description = "用户编码", example = "U001")
      private String userCode;

      /** 创建时间 */
      @JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss", timezone = "GMT+8")
      @Schema(description = "创建时间", example = "2026-04-07 15:45:30")
      private LocalDateTime createTime;
  }
  ```
- ✗ 反例
  ```java
  @Data
  public class SysUserCommonVO {
      private String userCode;                        // 缺少 @Schema
      @Schema(description = "密码") private String password;  // VO 暴露密码
      private LocalDateTime createTime;               // 缺少 @JsonFormat
  }
  ```

### 6.4 审计字段

所有业务表必须包含以下 8 个审计字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `create_tenant` | bigint | 创建时所属租户ID |
| `create_dept` | bigint | 创建时所属部门ID |
| `create_role` | bigint | 创建时使用角色ID |
| `create_by` | bigint | 创建人用户ID |
| `create_at` | timestamp | 创建时间 |
| `update_by` | bigint | 最后更新人用户ID |
| `update_at` | timestamp | 最后更新时间 |
| `is_deleted` | varchar(20) | 逻辑删除标记（NOT_DELETED / DELETED） |
| `deleted_at` | timestamp | 删除时间（可空） |

- ✓ 正例
  ```java
  /** 创建时所属租户ID */
  @Schema(description = "创建时所属租户ID", example = "0")
  @TableField(value = "create_tenant")
  private Long createTenant;

  /** 创建时间 */
  @Schema(description = "创建时间", format = "date-time", example = "2026-06-12 15:45:30")
  @JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss", timezone = "GMT+8")
  @TableField(value = "create_at")
  private LocalDateTime createAt;
  ```
- ✗ 反例
  ```java
  private Long createBy;          // 缺少 @TableField/@Schema/@JsonFormat
  private Date createTime;        // 使用 Date 而非 LocalDateTime，字段名 create_time 而非 create_at
  // 缺少 is_deleted 字段
  ```

### 6.5 软删除

统一使用 `is_deleted` 字段（`GlobalEnum.Deleted.NOT_DELETED` / `DELETED`），删除时置为 `DELETED` 并记录 `deleted_at`，禁止物理删除业务数据。

- ✓ 正例
  ```java
  // 查询时过滤未删除
  SysUser user = sysUserMapper.selectOne(new LambdaQueryWrapper<SysUser>()
          .eq(SysUser::getUserName, param.getUsername())
          .eq(SysUser::getIsDeleted, GlobalEnum.Deleted.NOT_DELETED.getCode()));
  ```
- ✗ 反例
  ```java
  sysUserMapper.deleteById(id);   // 直接物理删除
  // 查询未过滤 is_deleted
  sysUserMapper.selectList(null);
  ```

### 6.6 树形结构

层级数据使用物化路径（materialized path）方案，字段包括：

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| `parent_id` | 父节点ID | `0` 表示根 |
| `path` | 物化路径 | `/101/111/` |
| `level` | 层级 | `1` 表示顶级 |
| `has_children` | 是否有子节点 | `true` / `false` |

- ✓ 正例
  ```java
  /** 物化路径 */
  @Schema(description = "物化路径", example = "/101/111/")
  @TableField(value = "path")
  private String path;

  /** 层级 */
  @Schema(description = "层级", example = "2")
  @TableField(value = "level")
  private Integer level;

  /** 是否有子节点 */
  @Schema(description = "是否有子节点", example = "true")
  @TableField(value = "has_children")
  private Boolean hasChildren;
  ```
- ✗ 反例
  ```java
  // 使用递归 parent_id 查询层级，无 path 字段
  private Long parentId;   // 仅靠 parent_id 递归，性能差
  ```

## 7. 异常处理规范

### 7.1 业务异常

业务校验失败统一抛出 `BusinessException`，默认错误码 500，可指定 code。

- ✓ 正例
  ```java
  if (user == null) {
      throw new BusinessException("用户不存在");
  }
  if ("DISABLED".equals(user.getStatus())) {
      throw new BusinessException("用户已被禁用");
  }
  // 需要指定错误码
  throw new BusinessException(400, "用户编码已存在");
  ```
- ✗ 反例
  ```java
  if (user == null) {
      return null;                          // 静默返回 null
  }
  if (user == null) {
      throw new RuntimeException("用户不存在");  // 应使用 BusinessException
  }
  throw new IllegalArgumentException("...");   // 应使用 BusinessException
  ```

### 7.2 全局异常处理

通过 `@RestControllerAdvice` + `@ExceptionHandler` 统一拦截，所有异常转换为 `ApiResponse` 返回，并记录日志。

- ✓ 正例
  ```java
  @Slf4j
  @RestControllerAdvice
  public class GlobalExceptionHandler {

      @ExceptionHandler(BusinessException.class)
      public ApiResponse handleBusinessException(BusinessException ex) {
          log.error("业务异常: {}", ex.getMessage(), ex);
          return ApiResponse.error(ex.getCode(), ex.getMessage());
      }

      @ExceptionHandler(NotLoginException.class)
      public ApiResponse handleNotLoginException(NotLoginException ex) {
          log.error("未登录异常: {}", ex.getMessage(), ex);
          return ApiResponse.error(401, ex.getMessage());
      }
  }
  ```
- ✗ 反例
  ```java
  // Controller 内部 try-catch 吞异常
  @PostMapping("/add")
  public ApiResponse addUser(@RequestBody SysUserAddRTO addParam) {
      try {
          iSysUserService.addUser(addParam);
      } catch (Exception e) {
          return ApiResponse.error("失败");   // 吞掉异常，未记日志
      }
  }
  ```

### 7.3 异常类型与错误码

| 异常类型 | 错误码 | 触发场景 |
| --- | --- | --- |
| `BusinessException` | 500（默认）/ 自定义 | 业务校验失败 |
| `MethodArgumentNotValidException` | 400 | 参数校验失败 |
| `NotLoginException` | 401 | 未登录 |
| `NotPermissionException` | 403 | 缺少权限 |
| `NotRoleException` | 403 | 缺少角色 |
| `NotSafeException` | 403 | 二级认证失败 |
| `DisableServiceException` | 403 | 账号被封禁 |
| `IOException` / `SQLException` | 500 | 系统异常 |
| `Exception` | 500 | 兜底 |

- ✓ 正例
  ```java
  @ExceptionHandler(MethodArgumentNotValidException.class)
  public ApiResponse handleMethodArgumentNotValidException(MethodArgumentNotValidException ex) {
      log.error("参数验证异常: {}", ex.getMessage(), ex);
      String errorMsg = ex.getBindingResult().getFieldErrors().stream()
              .map(fieldError -> fieldError.getField() + ": " + fieldError.getDefaultMessage())
              .collect(Collectors.joining("; "));
      return ApiResponse.error(400, "参数验证失败: " + errorMsg);
  }
  ```
- ✗ 反例
  ```java
  @ExceptionHandler(Exception.class)
  public ApiResponse handleException(Exception ex) {
      return ApiResponse.error(200, "成功");   // 兜底异常返回成功，错误码错误
  }
  ```

### 7.4 异常处理禁忌

- ✗ 反例（吞掉异常）
  ```java
  try {
      iSysUserService.addUser(addParam);
  } catch (BusinessException e) {
      // 空的 catch，异常被吞
  }
  ```
- ✓ 正例
  ```java
  try {
      Map<String, List<String>> fieldMap = JSON.parseObject(perm.getFieldPermissions(), Map.class);
  } catch (Exception e) {
      log.error("字段权限解析失败: {}", e.getMessage(), e);   // 至少记录日志
  }
  ```

## 8. 日志规范

### 8.1 日志框架与级别

统一使用 SLF4J + Logback，类上标注 `@Slf4j` 注解（切面类可使用 `LoggerFactory.getLogger`）。日志级别：

| 级别 | 使用场景 |
| --- | --- |
| ERROR | 异常堆栈、业务失败、第三方调用失败 |
| WARN | 可恢复的异常、降级、跳过 |
| INFO | 关键业务操作（登录、新增、删除）、启动信息 |
| DEBUG | 调试信息，生产关闭 |
| TRACE | 详细步骤，生产关闭 |

- ✓ 正例
  ```java
  @Slf4j
  public class GlobalExceptionHandler {
      public ApiResponse handleBusinessException(BusinessException ex) {
          log.error("业务异常: {}", ex.getMessage(), ex);   // ERROR 记录异常
          return ApiResponse.error(ex.getCode(), ex.getMessage());
      }
  }
  ```
- ✗ 反例
  ```java
  System.out.println("用户不存在");              // 禁止用 System.out
  log.info("用户不存在: " + user.getId());       // 禁止字符串拼接，应使用 {} 占位符
  log.error("失败", e.getMessage());             // 缺少异常堆栈对象
  ```

### 8.2 日志格式

使用 `{}` 占位符，禁止字符串拼接；记录异常时必须把 `Throwable` 对象作为最后一个参数。

- ✓ 正例
  ```java
  log.error("业务异常: {}", ex.getMessage(), ex);
  log.info("用户登录成功, userId={}, tenantCode={}", userId, tenantCode);
  ```
- ✗ 反例
  ```java
  log.error("业务异常: " + ex.getMessage());              // 字符串拼接
  log.error("业务异常: {}", ex.getMessage());             // 缺少异常对象，丢失堆栈
  log.error(String.format("异常: %s", ex.getMessage()));  // 使用 String.format
  ```

### 8.3 操作日志

使用 `@OperationLog` 注解 + `OperationLogAspect` 切面自动记录操作行为，注解属性包括 `title`、`businessType`、`operatorType`、`isSaveRequestData`、`isSaveResponseData`、`excludeParams`。

- ✓ 正例
  ```java
  @OperationLog(title = "用户管理", businessType = BusinessType.INSERT)
  @PostMapping("/add")
  public ApiResponse addUser(@Valid @RequestBody SysUserAddRTO addParam) {
      Integer affectedRows = iSysUserService.addUser(addParam);
      return ApiResponse.success(affectedRows);
  }
  ```
- ✗ 反例
  ```java
  @PostMapping("/add")
  public ApiResponse addUser(@Valid @RequestBody SysUserAddRTO addParam) {
      log.info("新增用户: {}", addParam);   // 手动记日志，未使用 @OperationLog
  }
  ```

### 8.4 敏感信息脱敏

密码、token、旧密码、新密码、确认密码等参数必须脱敏，禁止记录到日志。`OperationLogAspect` 已内置 `EXCLUDE_PARAMS = Arrays.asList("password", "oldPassword", "newPassword", "confirmPassword", "token")`。

- ✓ 正例
  ```java
  // 切面内置排除敏感参数
  private static final List<String> EXCLUDE_PARAMS = Arrays.asList(
      "password", "oldPassword", "newPassword", "confirmPassword", "token");
  ```
- ✗ 反例
  ```java
  log.info("用户登录, password={}", param.getPassword());   // 明文打印密码
  log.info("token={}", StpUtil.getTokenValue());             // 打印 token
  ```

## 9. 安全规范

### 9.1 认证

采用 Sa-Token + JWT 无状态认证，登录成功后调用 `StpUtil.login(userId)`，用户上下文存入 Session。

- ✓ 正例
  ```java
  // 校验通过后执行登录
  StpUtil.login(user.getId());

  // 用户上下文存入 Session
  StpUtil.getSession().set(GlobalConstant.Session.USER_CONTEXT, userContext);
  ```
- ✗ 反例
  ```java
  // 自己实现 token 生成，未使用 Sa-Token
  String token = UUID.randomUUID().toString();
  redis.set(token, userId);
  ```

### 9.2 权限控制

接口权限通过 `@SaCheckPermission` / `@SaCheckRole` 注解声明式控制。

- ✓ 正例
  ```java
  @SaCheckPermission("user:add")
  @PostMapping("/add")
  public ApiResponse addUser(@Valid @RequestBody SysUserAddRTO addParam) { }

  @SaCheckRole("ADMIN")
  @PutMapping("/review")
  public ApiResponse reviewTenant(@Valid @RequestBody SysTenantReviewRTO reviewParam) { }
  ```
- ✗ 反例
  ```java
  @PostMapping("/add")
  public ApiResponse addUser(@Valid @RequestBody SysUserAddRTO addParam) {
      // 手动判断权限
      if (!StpUtil.hasPermission("user:add")) {
          throw new BusinessException("无权限");
      }
  }
  ```

### 9.3 密码安全

密码使用 BCrypt 加密存储，禁止明文存储与明文比较。

- ✓ 正例
  ```java
  // 注册/修改时加密
  String hashed = BCrypt.hashpw(rawPassword);
  user.setPassword(hashed);

  // 登录时校验
  if (!BCrypt.checkpw(param.getPassword(), user.getPassword())) {
      throw new BusinessException("密码错误");
  }
  ```
- ✗ 反例
  ```java
  user.setPassword(param.getPassword());                 // 明文存储
  if (!param.getPassword().equals(user.getPassword())) { // 明文比较
      throw new BusinessException("密码错误");
  }
  ```

### 9.4 SQL 注入防护

统一使用 MyBatis-Plus 参数化查询（`LambdaQueryWrapper`），禁止 SQL 字符串拼接。

- ✓ 正例
  ```java
  SysUser user = sysUserMapper.selectOne(new LambdaQueryWrapper<SysUser>()
          .eq(SysUser::getUserName, param.getUsername())
          .eq(SysUser::getIsDeleted, GlobalEnum.Deleted.NOT_DELETED.getCode()));
  ```
- ✗ 反例
  ```java
  String sql = "select * from sys_user where user_name = '" + param.getUsername() + "'";
  sysUserMapper.selectBySql(sql);   // SQL 拼接，存在注入风险
  ```

### 9.5 越权防护

数据权限通过 `@DataScope` 注解 + `DataScopeAspect` 切面控制，按角色 `dataScope`（ALL/DEPT/SELF 等）自动注入过滤条件。

- ✓ 正例
  ```java
  @DataScope(deptAlias = "d", userAlias = "u")
  @GetMapping("/page")
  public ApiResponse queryUserPage(@Valid PageCommonRTO page) { }
  ```
- ✗ 反例
  ```java
  // 直接查询全表，未做数据权限过滤
  sysUserMapper.selectList(null);
  ```

### 9.6 XSS / CSRF

- 输入校验：通过 `@Valid` + `@Pattern` / `@Size` 校验入参。
- 输出编码：Fastjson2 序列化时自动转义。
- CSRF：Sa-Token 基于 Token 认证，天然免疫 CSRF。

## 10. 版本控制规范

### 10.1 分支管理

| 分支 | 用途 | 命名 |
| --- | --- | --- |
| `main` | 生产分支 | `main` |
| `develop` | 开发集成分支 | `develop` |
| `feature` | 功能开发 | `feature/{module}`，如 `feature/iam` |
| `hotfix` | 线上修复 | `hotfix/{issue}`，如 `hotfix/issue-101` |
| `release` | 预发布 | `release/{version}`，如 `release/1.0.0` |

- ✓ 正例
  ```
  feature/iam
  hotfix/issue-128
  release/1.2.0
  ```
- ✗ 反例
  ```
  feature_iam               // 应使用 /
  my-branch                 // 无前缀
  feature/iam-new-feature   // feature 分支名过于冗长
  ```

### 10.2 提交信息

格式：`type(scope): subject`

| type | 含义 |
| --- | --- |
| feat | 新功能 |
| fix | 缺陷修复 |
| docs | 文档 |
| style | 格式（不影响代码逻辑） |
| refactor | 重构 |
| test | 测试 |
| chore | 构建/工具 |

`scope` 为模块名（iam/tenant/common/billing 等），`subject` 简明描述。

- ✓ 正例
  ```
  feat(iam): 新增用户批量删除接口
  fix(tenant): 修复租户切换时上下文未清理的问题
  docs(common): 补充 OperationLog 注解说明
  refactor(audit): 重构审计日志切面，统一脱敏逻辑
  ```
- ✗ 反例
  ```
  update                       // 无 type、无 scope
  fix: 修了个 bug              // subject 模糊
  feat(IAM): 新增接口           // scope 应小写
  feat: 新增用户接口、租户接口   // 一个提交包含多个不相关变更
  ```

### 10.3 代码审查

- PR 必须至少 1 人 review 通过方可合并。
- CI（编译、单元测试、代码扫描）必须全部通过。
- 禁止直接 push 到 `main` / `develop`，必须通过 PR 合并。

### 10.4 版本号

采用 SemVer 语义化版本：`MAJOR.MINOR.PATCH`

- `MAJOR`：不兼容的 API 变更。
- `MINOR`：向下兼容的功能新增。
- `PATCH`：向下兼容的缺陷修复。

- ✓ 正例：`1.2.0`、`1.2.1`、`2.0.0`
- ✗ 反例：`v1`、`1.2`、`20260704`

## 11. 测试规范

### 11.1 单元测试

- 框架：JUnit 5 + Mockito。
- 测试类命名：`XxxTest`，与被测类同包（`src/test/java`）。
- 方法命名：`testXxx_场景_期望结果`。
- 核心业务逻辑覆盖率 ≥ 80%。

- ✓ 正例
  ```java
  class ISysUserServiceTest {

      @Mock private SysUserMapper sysUserMapper;
      @InjectMocks private SysUserServiceImpl sysUserService;

      @Test
      void testAddUser_用户编码已存在_抛出BusinessException() {
          // given
          when(sysUserMapper.selectOne(any())).thenReturn(new SysUser());
          SysUserAddRTO rto = new SysUserAddRTO().setUserCode("U001");
          // when & then
          assertThrows(BusinessException.class, () -> sysUserService.addUser(rto));
      }
  }
  ```
- ✗ 反例
  ```java
  class UserTest {                                  // 测试类未以 XxxTest 命名
      @Test
      void test1() {                                // 方法名无场景无期望
          // 无断言
      }
  }
  ```

### 11.2 集成测试

- 使用 `@SpringBootTest` 启动上下文。
- 使用 Testcontainers 管理 PostgreSQL / Redis / RabbitMQ。
- 测试数据使用 `@Transactional` 自动回滚，不污染数据库。

- ✓ 正例
  ```java
  @SpringBootTest
  @Transactional
  class SysUserControllerIT {

      @Autowired private SysUserController sysUserController;

      @Test
      void testAddUser_合法参数_返回成功() {
          SysUserAddRTO rto = new SysUserAddRTO()
              .setUserCode("U999")
              .setUserName("testuser")
              .setPassword("abc123456");
          ApiResponse response = sysUserController.addUser(rto);
          assertTrue(response.isSuccess());
      }
  }
  ```
- ✗ 反例
  ```java
  @SpringBootTest
  class SysUserControllerIT {
      @Test
      void testAddUser() {
          sysUserController.addUser(rto);
          // 真实写入数据库，未回滚，污染数据
          // 无断言
      }
  }
  ```

### 11.3 测试数据

- 禁止依赖预置的数据库数据，应自行构造。
- 使用 `@Transactional` 回滚，或 `@BeforeEach` 清理。

## 12. 数据库规范

### 12.1 表命名

- 系统表：`sys_xxx`（如 `sys_user`、`sys_tenant`、`sys_role`、`sys_perm`）。
- 业务表：`biz_xxx`（如 `biz_order`、`biz_contract`）。
- 全小写 snake_case。

- ✓ 正例
  ```sql
  create table sys_user ( ... );
  create table biz_order ( ... );
  ```
- ✗ 反例
  ```sql
  create table SysUser ( ... );   -- 含大写
  create table users ( ... );     -- 缺少前缀
  create table biz_Order ( ... ); -- 大小写混合
  ```

### 12.2 字段命名与注释

- 字段全小写 snake_case。
- 表和字段必须有 `comment`（`comment on table` / `comment on column`）。

- ✓ 正例
  ```sql
  create table sys_user (
      id             bigint       not null primary key,
      user_code      varchar(50)  not null,
      user_name      varchar(50)  not null,
      create_at      timestamp(6) not null
  );

  comment on table sys_user is '用户表';
  comment on column sys_user.id is '主键ID';
  comment on column sys_user.user_code is '用户编码';
  comment on column sys_user.user_name is '用户名';
  comment on column sys_user.create_at is '创建时间';
  ```
- ✗ 反例
  ```sql
  create table sys_user (
      id        bigint,           -- 缺少 not null / primary key
      UserCode  varchar(50),      -- 含大写
      user_name varchar(50)
  );
  -- 缺少 comment on table / comment on column
  ```

### 12.3 主键

- 主键字段名固定为 `id`，类型 `bigint`。
- Java 侧使用 `IdType.ASSIGN_ID`（雪花算法），数据库侧不设自增。

- ✓ 正例
  ```sql
  create table sys_user (
      id bigint not null primary key,
      ...
  );
  ```
  ```java
  @TableId(value = "id", type = IdType.ASSIGN_ID)
  private Long id;
  ```
- ✗ 反例
  ```sql
  id serial primary key,            -- 使用自增，与 ASSIGN_ID 不一致
  user_id bigint primary key,       -- 主键名不是 id
  ```
  ```java
  @TableId(type = IdType.AUTO)      // 与 ASSIGN_ID 规范不一致
  private Long id;
  ```

### 12.4 审计字段

所有业务表必须包含 8 个审计字段（详见 6.4）：`create_tenant` / `create_dept` / `create_role` / `create_by` / `create_at` / `update_by` / `update_at` / `is_deleted`，删除时补充 `deleted_at`。

- ✓ 正例
  ```sql
  create table sys_user (
      ...,
      create_tenant  bigint       not null,
      create_dept    bigint       not null,
      create_role    bigint       not null,
      create_by      bigint       not null,
      create_at      timestamp(6) not null,
      update_by      bigint       not null,
      update_at      timestamp(6) not null,
      is_deleted     varchar(20)  not null,
      deleted_at     timestamp(6)
  );
  ```
- ✗ 反例
  ```sql
  create table biz_order (
      id bigint primary key,
      order_code varchar(50)
      -- 缺少全部审计字段
  );
  ```

### 12.5 索引

- 普通索引：`idx_表名_字段名`。
- 唯一索引：`uk_表名_字段名`。
- 高频查询字段、外键关联字段必须建索引。

- ✓ 正例
  ```sql
  create index idx_sys_user_user_name on sys_user(user_name);
  create unique index uk_sys_user_email on sys_user(email);
  create index idx_sys_user_create_tenant on sys_user(create_tenant);
  ```
- ✗ 反例
  ```sql
  create index idx1 on sys_user(user_name);                -- 索引名无表名字段名
  create unique index email_uniq on sys_user(email);       -- 未使用 uk_ 前缀
  ```

### 12.6 JSONB 字段

字段级权限等半结构化数据使用 PostgreSQL `jsonb` 类型存储（如 `field_operation` 字段）。

- ✓ 正例
  ```sql
  create table sys_perm_policy (
      ...,
      field_operation jsonb
  );
  comment on column sys_perm_policy.field_operation is '字段级权限操作，JSON 格式：{"table_name": {"field_name": ["READ","CREATE","UPDATE"]}}';
  ```
  ```java
  // Java 侧解析
  Map<String, List<String>> fieldMap = JSON.parseObject(perm.getFieldPermissions(), Map.class);
  ```
- ✗ 反例
  ```sql
  create table sys_perm_policy (
      field_operation varchar(2000)   -- 使用 varchar 存 JSON，无法使用 JSONB 索引
  );
  ```

### 12.7 软删除约定

`is_deleted` 字段使用字符串枚举值（`NOT_DELETED` / `DELETED`），而非 0/1。

- ✓ 正例
  ```sql
  is_deleted varchar(20) not null default 'NOT_DELETED'
  ```
  ```sql
  INSERT INTO sys_user (..., is_deleted) VALUES (..., 'NOT_DELETED');
  ```
- ✗ 反例
  ```sql
  is_deleted tinyint default 0     -- 使用 0/1，与枚举不一致
  is_deleted boolean default false -- 类型错误
  ```
